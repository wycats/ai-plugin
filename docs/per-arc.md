# PER Arc

A PER arc preserves what a series of prepare–execute–review cycles has taught
us about the work. A later cycle should be able to use that understanding
without reconstructing every earlier attempt.

The [PER workflow](../skills/workflows/per-cycle/SKILL.md) owns the cycle and
its handoffs. This note describes the continuity that can help when work spans
several cycles. Keep it in the project's existing working record, or create a
small note when that would save substantial reconstruction. Its usefulness
depends on whether it changes how the next cycle proceeds.

## What carries forward

Begin with the change being pursued and the source of that direction. Carry
the expectations still guiding the work, observations that support or qualify
them, and discoveries that changed the approach. Keep enough connection to the
artifacts that a later reader can check an important claim against its source.

An earlier explanation may have become inadequate while its observations
remain useful. Preserve what those observations now mean for the work. When
an uncertainty remains consequential, name what would help resolve it and how
the answer could change the next move.

The tension is continuity of understanding against maintenance cost. A record
that retains every attempted route makes the current one hard to recover. A
record that retains only the next action loses the reasons for taking it.
Keep the evidence and unresolved questions that still shape the work.

## Purpose and evidence

When [vision steering](../skills/workflows/steer-by-vision/SKILL.md) supplied
the current direction, retain its relationship to the intended experience and
the condition that should prompt reconsideration. Refer to the authoritative
source of that direction so the working record stays connected to it. A
bounded task can carry its purpose directly from the user's request.

Record the reach of the evidence. A check that could not reach the changed
behavior can still teach us about a dependency. A working dependency can make
the next experiment possible. Implementation checks can pass while an
improvement in ordinary use remains to be observed. Preserve these distinctions
when they affect what can be concluded or attempted next.

For consequential external actions, retain whether the action happened and
what was observed afterward. A later attempt needs that information to
determine whether repeating the action is appropriate.

## Updating the record

After a cycle changes the understanding or completes a meaningful part of the
work, revise the live account. Keep the intended change, the evidence that now
supports the approach, the remaining uncertainty, and the next useful move
easy to find. Compress earlier attempts as their details stop affecting those
judgments; retain source pointers for findings that may need reexamination.

If evidence calls the direction into question, record the finding and the
choice it creates. Return project-level selection to vision steering when
needed. Once a direction is chosen, update the account so the next cycle begins
from that choice and the reasons for it.

The [archived pipeline-hardening arc](../PER-ARC.md) records an earlier use of
this approach. Its historical decisions and format belong to that effort;
current work should use the amount of continuity it needs.
