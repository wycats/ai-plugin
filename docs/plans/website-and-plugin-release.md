# Website and plugin release orientation

Working direction · 2 November 2026

We are bringing the website and plugin to a release that makes our approach to working with agents understandable, usable, and worth returning to. A reader should be able to recognize a difficulty in their own work, understand how the approach might help, try it through an ordinary installation, and use what happens to deepen that understanding. The website and plugin carry the same ideas into different settings; experience with either can reveal something the other needs to express better.

The immediate priority is a satisfying edition of the website using a fixed snapshot of the current Fellowhand work. From there, we will develop one concrete route from reading to use, learn from a consequential work episode, and carry the resulting refinements through the language, composition, and runtime delivery. This order gives us completed pieces while keeping the larger inquiry alive.

## The experience we want

The plugin should help an agent develop the implications of the understanding it shares with the user. As work unfolds, a discovery can change what earlier observations mean and what becomes worth doing next. We want the agent to participate in that change of understanding: noticing a consequential relationship, pursuing it, and bringing its judgment back into the collaboration.

The website makes that approach available to a person encountering it for the first time. Building together supplies a connected account; the fuller stances and workflows let readers investigate particular difficulties. The reading experience should feel like the margins of a thoughtful book that you can move through. Typography, illustration, related readings, and the ability to return to a passage all support that experience. Someone should gain something from reading it even before installing the plugin.

Installation carries the account into actual work. The reader should find recognizable language and useful entry points, and the host should deliver the guidance that the described experience depends on. Deeper consultation should become useful as the work gives the agent more specific questions. Successful work with little additional reading is a valid outcome too.

The release succeeds when these relationships hold together: the reading is inviting, the route into use is clear, and the resulting behavior gives us concrete grounds for the claims we make.

## Tensions that should guide the work

**A finished edition and an evolving inquiry.** The website needs enough completeness to be useful now. The theory will continue to develop through experience. A release can present a coherent account with honest limits; each unresolved question needs a reason to hold up that release.

**Visual character and effortless reading.** The manuscript vocabulary gives the work a distinctive voice. Its success depends on actual passages, headings, navigation, and small screens. Fellowhand can continue improving independently while the site uses a named, reproducible snapshot. We revisit that snapshot when a visible reading problem or a compelling improvement justifies the integration work.

**Shared meaning and different forms of use.** A story, stance, workflow, and runtime entry point expose different amounts of detail. Each should help its reader reason locally while preserving a route to the fuller account. Improving the website may uncover a conceptual gap; implementing delivery may expose an ambiguity in composition. Those discoveries belong back in the source that owns the idea.

**Useful guidance and the cost of attention.** More loaded text and more skill calls can help or distract. We judge guidance by what it enables the agent to notice and do. Delivery, recognition of relevance, and consequential judgment are separate questions, and each suggests a different intervention.

**Ordinary experience and bounded evidence.** A controlled trial can isolate a mechanism. An installed workflow establishes whether people encounter it in practice. We need both kinds of evidence where they affect the release, keeping each claim attached to the route actually exercised. The deferred Glade example is especially relevant: an improved implementation can work while the ordinary command still reaches its predecessor.

**Generality and concrete learning.** Curated subsets, writing workflows, and host integration all raise worthwhile questions. We will develop their general account through examples that require a decision. An attractive abstraction earns release scope when it makes the chosen experience work or explains a recurring difficulty.

## A theory for interleaving the work

Our working hypothesis is that short, complete routes through explanation and use will teach us more than finishing each discipline separately. The site gives us an account to examine. Installation tests whether that account reaches work. An episode tests what the guidance contributes. The resulting distinction can then improve both the implementation and the explanation.

For each iteration, choose an experience or consequential judgment, make the smallest coherent change, inspect what happened, and update the account before choosing the next move. If the result changes the significance of an earlier issue, revise the order. A dependency belongs in the critical path when the current experience actually needs it.

Review the assembled site with a selected Fellowhand snapshot: opening, typography, illustrations, Contents, related readings, and return to the original passage. Include both themes, narrow layouts, enlarged text, and keyboard navigation. Finish the issues that interrupt reading or make the edition feel unresolved.

The stopping point is an edition we would happily send someone to read. A larger folding map, richer initials, and further glyph refinement remain available responses to observed needs. This milestone can be reviewed and prepared independently of the later plugin changes.

### Connect one reading to ordinary use

Choose a representative journey from a passage to a fuller resource, installation, and relevant work. Use that journey to scope the supporting-context integration and state which host experience it establishes.

While implementation proceeds, we can recover a real work episode and review the relevant canonical language. Those activities inform the same question without requiring every open thread to advance at once.

### Let an episode refine the model

Reconstruct a moment where the user supplied an important implication: what the agent knew, what guidance it had, what it consulted, and how the user's contribution changed the work. The Glade ordinary-workflow example is a candidate. Read it beside PER and Architectural Distillation before deciding whether the missing relationship belongs in those resources, in delivery, or elsewhere.

A bounded comparison is useful when it can change that editing decision. The stopping point is a specific refinement with a clear reason, carried into the relevant reading and installed experience. If the existing language already expresses the relationship well, the next step may be delivery or discovery work.

### Generalize where the route demands it

Use the working route to clarify which dependencies must be available for consultation, which must be activatable, and how a curated subset preserves those relationships. The richer relationship map belongs here if reading and discovery repeatedly need it. This lets navigation express relationships we have learned to use, with a concrete purpose for the additional interface.

### Assemble and judge the release

Re-read the story, resource descriptions, installation guidance, and representative workflows as one account. Inspect the actual website and installed plugin against that account. Complete the relevant package, interaction, and runtime checks, then prepare the changes for review and publication approval.

The release boundary is a satisfying reading edition and a supported route into useful work, with explanations that accurately describe both. Further font work, additional host qualification, broader subset support, and experimental workflows can continue from that stable point.

## Coordination and continuity

As we iterate, keep the current bet, what we learned, and the next unresolved dependency visible beside this orientation. Update the orientation when the target or the relationships change. The history and experiments remain supporting evidence; the plan should continue to tell us what is worth doing next.
